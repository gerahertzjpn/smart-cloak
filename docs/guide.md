# はじめてガイド：このプロジェクトでの作業のしかた

プログラミングやチーム開発が初めてでも大丈夫です。
わからないことがあれば、AIに「docs/guide.md を使って説明して」と頼んでください。

---

## 0. 最初の準備（1回だけ）

1. [GitHub](https://github.com) のアカウントを作り、**ログイン名**を DB担当に送る。
2. GitHub から招待メールが届いたら「**Accept invitation**」を押す。
3. [GitHub Desktop](https://desktop.github.com) をインストールする
   （コマンドが苦手な人におすすめ。ボタン操作で pull / ブランチ / コミット / push ができる）。
4. GitHub Desktop で「**Clone a repository**」→ `gerahertzjpn/smart-cloak` を選ぶ。
5. 自分のAIツールで、そのフォルダを開く（下の「AIツール別の使い方」を参照）。
6. AIに最初にこう送る：

   > 「AGENTS.md と docs/guide.md を読んで、このプロジェクトの内容と、
   > 私たちの作業の流れを初心者向けに説明してください。」

これで、AIがこのガイドの内容をあなたに合わせて説明してくれます。

---

## AIツール別の使い方

AIがルール（`AGENTS.md`）を**自動で読むかどうか**は、ツールによって違います。

| ツール                                             | ルールを読む？                    | やること                           |
|----------------------------------------------------|-----------------------------------|------------------------------------|
| Claude Code                                        | 自動（`CLAUDE.md` → `AGENTS.md`） | プロジェクトのフォルダを開くだけ   |
| Google Antigravity（Gemini を使う人向け）          | 自動（`AGENTS.md`、`GEMINI.md`）  | 下の「Gemini を使いたい人へ」を参照 |
| Codex / Cursor / GitHub Copilot                    | 自動（`AGENTS.md`）               | プロジェクトのフォルダを開くだけ   |
| ブラウザのチャット（Gemini、ChatGPT、Claude の Web版） | **読まない**（PCのファイルが見えない） | 下の「スタート用メッセージ」を使う |

### ブラウザのチャットを使う場合

ブラウザのチャットは、あなたのPCのファイルもリポジトリも見えません。
そのため、**毎回の会話の最初に**次の2つをします。

1. `AGENTS.md` と `docs/guide.md` をファイルとして添付する。
2. 次のメッセージを貼る：

   > 「これからチーム開発のプロジェクトを手伝ってもらいます。
   > 添付の AGENTS.md（プロジェクトのルール）と docs/guide.md（作業の流れ）を読み、
   > 必ずそのルールに従ってください。
   > 私はプログラミング初心者なので、何をするか・なぜかを日本語でわかりやすく説明しながら進めてください。
   > あなたは私のPCのファイルを直接見られないので、必要なファイルがあれば中身を貼るよう私に頼んでください。」

注意：ブラウザのチャットが書いたコードは、自分でファイルに貼り付けることになるため、
**間違ったファイルに貼る・一部だけ貼る**といったミスが起きやすいです。
できれば、フォルダを直接開けるツール（Google Antigravity、Claude Code など）を使ってください。

### Gemini を使いたい人へ（Google Antigravity）

ブラウザの Gemini（gemini.google.com）の代わりに、**Google Antigravity** を使うと、
Gemini がプロジェクトのフォルダを直接読み書きでき、ルール（`AGENTS.md`）も自動で読みます。

> 注意：以前の「Gemini CLI」は、2026年6月から企業向けのみになりました。
> 個人・無料で使う場合は Antigravity を使います。

**準備**

1. [ダウンロードページ](https://antigravity.google/download)を開く。
2. 初心者には **Antigravity App**（ボタンで操作できるアプリ）がおすすめ。
   ターミナルに慣れている人は **Antigravity CLI** でもOK
   （ページに自分のOS用のインストールコマンドが表示されます）。
3. 起動して「Sign in」を押し、**個人の Google アカウント**でログインする（Free プランあり）。
   - 学校の Google Workspace アカウントには Antigravity のプランが含まれていないため、
     **個人のアカウント**を使ってください。
4. GitHub Desktop で clone した `smart-cloak` フォルダを開く
   （CLI の場合は、そのフォルダでターミナルを開いて `agy` と入力）。
5. 最初にこう送る：

   > 「AGENTS.md と docs/guide.md を読んで、このプロジェクトの内容と、
   > 私たちの作業の流れを初心者向けに説明してください。」

   ルールに沿った説明（日本語、初心者向け）が返ってくれば準備完了です。

**注意**
- 無料プランには使用量の上限があります。上限に近づくと画面に表示されます。
- 有料のクレジットを使う設定（Use AI Credits）は、自分で理解してからオンにしてください。

## 1. 3つの場所

```
 自分のPC                  GitHub                      Google Cloud
（作業机）                （チーム共有の本棚）          （本番の店舗）
┌──────────┐  push   ┌──────────────────┐  反映   ┌──────────────────┐
│ 下書きを │ ──────▶ │ main = 正式版    │ ──────▶ │ Cloud SQL（DB）  │
│ 書く場所 │ ◀────── │ 全員がここを見る │         │ Cloud Storage    │
└──────────┘  pull   └──────────────────┘         │ （写真）         │
                                                   └──────────────────┘
```

- **自分のPC**：自由に書いて試す場所。壊しても他の人には影響しない。
- **GitHub**：チームの「正式版」が置いてある場所。全員が同じものを見る。
- **Google Cloud**：実際にシステムが動く場所。DB担当が管理する。

大事なルール：**正式版（main）は、確認されたものしか入らない。**

## 2. 用語集

| 用語              | ひとことで                                    | たとえ                    |
|-------------------|-----------------------------------------------|---------------------------|
| リポジトリ        | プロジェクトのファイル一式                    | チームの共有フォルダ      |
| コミット          | 変更の保存（メモ付き）                        | ゲームのセーブ            |
| ブランチ          | 自分専用の作業コピー                          | 原稿のコピーに書き込む    |
| `main`            | 正式版のブランチ                              | 提出用の清書              |
| push / pull       | GitHub へ送る / GitHub から受け取る           | アップロード / ダウンロード |
| Pull Request (PR) | 「この変更を正式版に入れてください」という申請 | 先生への提出               |
| レビュー          | 他のメンバーが PR を確認すること              | 友達に読んでもらう        |
| マージ            | PR を正式版に取り込むこと                     | 清書に書き写す            |
| 自動チェック (CI) | PR ごとに GitHub が自動で動かすテスト         | 提出前の自動採点          |
| マイグレーション  | DB の構造を変える手順書（番号つき）           | 家のリフォーム記録        |

## 3. 1つのタスクの流れ

```
① 最新版をもらう → ② ブランチを作る → ③ AIと作業 → ④ コミット
        → ⑤ push → ⑥ PRを作る → ⑦ 自動チェック＋レビュー → ⑧ マージ
```

| 手順 | やること                         | コマンド / 操作                              |
|------|----------------------------------|----------------------------------------------|
| ①    | 最新の正式版を取得               | `git switch main` → `git pull`               |
| ②    | 自分のブランチを作る             | `git switch -c 名前`（例：`feature/qr-scan`） |
| ③    | AIにタスクを頼む                 | 下の「AIへの頼み方」を参照                   |
| ④    | 変更を保存                       | `git add -A` → `git commit -m "何をしたか"`  |
| ⑤    | GitHub へ送る                    | `git push -u origin 名前`                    |
| ⑥    | PR を作る                        | GitHub の画面で「Compare & pull request」    |
| ⑦    | 緑のチェック ✅ とメンバーの承認を待つ | 赤 ❌ なら直して、もう一度 ④⑤           |
| ⑧    | マージ                           | 承認されたら「Merge pull request」           |

コマンドがわからなければ、AIに「① から ⑤ までやって、何をしているか説明して」と頼んでOKです。

## 4. AIへの頼み方

良い頼み方の例：

> 「AGENTS.md と docs/ を読んでから、frontend に引換券QRを読み取る画面を作ってください。
> まず何をするか説明して、私がOKしてから作業してください。」

> 「この PR の自動チェックが赤になりました。原因を日本語でわかりやすく説明してください。」

> 「git の今の状態を説明してください。何か危ないことはありますか？」

ポイント：
- **最初に「AGENTS.md を読んで」と言う**（多くのAIは自動で読みますが、念のため）。
- **「先に説明して」と頼む**。何をするか理解してから進めてもらう。
- **AIが「ルールでできません」と言ったら、それは正しい動き**。理由と代わりの方法を聞く。

## 5. なぜこんなルールがあるの？

| ルール                              | 理由                                                  |
|-------------------------------------|-------------------------------------------------------|
| main に直接書かない                 | 1人（1つのAI）のミスで全員の作業が壊れないように      |
| 自分の担当フォルダだけ変更する      | 他の人の作業と衝突しないように                        |
| DB の変更はマイグレーションで       | 本番のDBと全員のコードの状態をそろえるため            |
| 古いマイグレーションは変えない      | すでに本番に適用済み。変えても本番には反映されない    |
| パスワードをコードに書かない        | GitHub に上がると、誰でも本番DBに入れてしまう         |
| PR は他の人が承認する               | 自分では気づかないミスを見つけるため                  |

## 6. 困ったとき

| 状況                                     | どうする                                                  |
|------------------------------------------|-----------------------------------------------------------|
| 自動チェックが赤 ❌                      | 「Details」を開き、エラーをAIに貼って説明してもらう       |
| 「conflict（コンフリクト）」と出た       | 同じ場所を2人が変更した。AIに説明を頼み、相手と相談する  |
| 間違えて main で作業していた            | コミット前なら `git switch -c 新しい名前` で移れる        |
| 他の人のフォルダを変えたくなった         | 変えずに、Issue でその人に頼む                            |
| DB にテーブルや項目を追加したい          | DB担当に相談する                                          |
| どうしてもわからない                     | 手を止めて、チームに聞く。壊すより聞くほうがずっと早い   |
